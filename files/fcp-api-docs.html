POST/v1/checkoutsCreate a checkout session
Checkout▾

Step 1 — WHAT TO BUY.

Submits cart intent: items, buyer, and the user-signed IntentMandate.
No payment information. The grand_total is unknown until the merchant
computes tax, shipping, and discounts server-side.

The merchant responds with a CartMandate — a merchant-signed document
containing the session_id, exact items, and grand_total. The agent
presents this to the user, who:
1. Sees the final price
2. Picks a payment handler from the merchant profile list (client-side)
3. Counter-signs the CartMandate (biometric / PIN on device)

Then the agent calls complete.

GET/v1/checkouts/{session_id}Retrieve a checkout session
Checkout▾

Returns current session state. Recommended: call GET immediately before
complete to confirm the CartMandate hasn't been invalidated by a
merchant-side change (inventory drop, pricing update).

The response always includes the current CartMandate and
`available_payment_handlers` so the agent can re-render the payment
selection UI if needed without refetching the merchant profile.

PATCH/v1/checkouts/{session_id}Update cart or buyer details
Checkout▾

Modifies an active session. Any change that affects pricing (add/remove
items, discount, shipping address to a different tax zone) invalidates
the current CartMandate and triggers a new one — the agent must
re-collect the user's counter-signature before completing.

Non-price changes (buyer email, phone, metadata) do not invalidate
the CartMandate.

Not accepted: `payment_handler_id` — that is submitted at complete.

POST/v1/checkouts/{session_id}/cancelCancel a checkout session
Checkout▾

Terminates the session from any pre-completion state.
- CartMandate is cryptographically voided
- CP is notified to invalidate any pre-staged token for this mandate_id
- CancelRecord appended to mandate chain for audit

Idempotent. Cannot cancel a completed session.
